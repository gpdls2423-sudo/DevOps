# 6주차 DevOps 실습: Dockerfile 및 ghcr.io 이미지 배포

## 1. 실습 목표
* Dockerfile의 주요 명령어(`FROM`, `WORKDIR`, `COPY`, `RUN`, `ENV`, `EXPOSE`, `CMD`)의 역할을 이해하고 직접 작성한다.
* 레이어 캐시(Layer Cache)의 동작 원리와 명령어 작성 순서의 중요성을 이해한다.
* 나만의 애플리케이션 이미지를 빌드하고 GitHub Container Registry(`ghcr.io`)에 태그 및 푸시(Push)하여 공유한다.
* 멀티 아키텍처 빌드(`buildx`)의 필요성과 환경 변수 우선순위(코드 < ENV < `-e`)를 직접 검증한다.

## 2. Dockerfile 주요 명령어 및 개념 정리

### (1) 주요 명령어 역할
* **`FROM`**: 이미지를 생성할 때 기반이 되는 베이스 이미지를 지정한다 (각 빌드 스테이지의 시작 point).
* **`WORKDIR`**: 컨테이너 내부의 작업 디렉터리를 설정한다 (지정한 디렉터리가 없으면 자동 생성).
* **`COPY <src> <dest>`**: 호스트 시스템의 파일이나 디렉터리를 컨테이너 이미지 내부로 복사한다.
* **`RUN`**: **이미지를 빌드하는 시점**에 실행되며, 결과가 새 레이어로 저장된다 (예: 패키지 설치).
* **`ENV`**: 이미지 내부에서 사용할 환경 변수의 기본값을 설정한다 (`docker run -e` 옵션으로 덮어쓰기 가능).
* **`EXPOSE`**: 컨테이너가 사용할 포트 번호를 문서화하는 용도이며, 실제 포트가 열리는 것은 아니다 (`-p` 옵션 필수).
* **`CMD`**: **컨테이너가 시작(실행)되는 시점**에 실행할 기본 명령어를 정의한다 (마지막 CMD만 효력 발생).

### (2) `RUN` vs `CMD` 차이점
* **`RUN`**: 붕어빵 틀(이미지)을 만드는 과정에서 필요한 작업을 수행 (빌드 시 1회 실행).
* **`CMD`**: 완공된 붕어빵 틀로 붕어빵(컨테이너)을 구워낼 때 시작 명령을 수행 (컨테이너 실행 시마다 수행).

### (3) 레이어 캐시(Layer Cache)의 원리 및 순서
* Dockerfile의 각 명령어는 읽기 전용 레이어(Layer)를 형성한다.
* 위쪽 단계의 레이어가 변경되면 그 아래의 모든 레이어는 캐시가 무효화되어 새로 빌드된다.
* **작성 팁**: 상대적으로 자주 변경되지 않는 라이브러리 설치 파일(`requirements.txt`)을 먼저 복사(`COPY`) 및 설치(`RUN`)한 뒤, 자주 수정되는 앱 소스 코드를 나중에 복사해야 재빌드 시간을 크게 단축할 수 있다.

## 3. 주요 실습 및 명령어 정리

### ① ghcr.io 로그인 및 이미지 빌드
```bash
# GitHub CLI를 통한 ghcr.io 로그인
gh auth token | docker login ghcr.io -u <GitHub_ID> --password-stdin

# Dockerfile 기반 이미지 빌드 (-t: 태그 지정)
docker build -t guestbook:v1 .

# 이미지 확인 및 실행
docker run -d -p 8081:5000 --name gb guestbook:v1
